## 確認環境

### デプロイ・起動手順
1. 依存パッケージのインストール
   ```bash
   pnpm install
   ```
2. 型チェック
   ```bash
   pnpm typecheck
   ```
3. lint/format チェック
   ```bash
   pnpm lint:fix && pnpm format
   ```
4. 全テスト実行（リグレッション確認）
   ```bash
   pnpm test
   ```
5. 開発サーバー起動（手動確認用）
   ```bash
   pnpm dev
   ```
   確認用URL: http://localhost:5173

### 前提条件
- Node.js 22.x
- pnpm がインストール済み
- `.env` ファイルにDB接続情報等が設定済み
- `pnpm db:migrate` でマイグレーション適用済み
- `pnpm db:seed` でシードデータ投入済み

## 確認項目

### 1. 顧客ランクドロップダウンの選択肢表示

- **目的:** 顧客ランクのドロップダウンに A/B/C/D の選択肢が表示されることを確認する
- **手順:**
  1. ログインする（admin / Admin123!）
  2. 顧客リストアプリのレコード追加ページにアクセスする
  3. 「Customer Rank」ドロップダウンをクリックする
- **期待結果:** ドロップダウンに「-----」「A」「B」「C」「D」の選択肢が表示される
- **確認ポイント:** 空のドロップダウンではないこと

### 2. レコード作成時のフィールド値保存

- **目的:** フォームに入力した値がDBに正しいフィールドコードで保存されることを確認する
- **手順:**
  1. レコード追加ページで以下を入力する:
     - Company: テスト株式会社
     - Department: 開発部
     - Contact: 山田太郎
     - Postal Code: 1000001
     - TEL: 0312345678
     - Address: 東京都千代田区
     - Customer Rank: A
     - Email: test@example.com
  2. 「Save」ボタンをクリックする
  3. レコード詳細画面に遷移することを確認する
  4. DBを確認し、records テーブルの fieldValues に以下のキーで値が保存されていることを確認:
     - `company_name`（`company` ではないこと）
     - `contact_name`（`person` ではないこと）
     - `customer_rank`（`rank` ではないこと）
- **期待結果:** 全フィールドが正しいフィールドコードで保存される
- **確認ポイント:** 特に修正対象の3フィールド（company_name, contact_name, customer_rank）のキー名

### 3. 既存レコード一覧での表示確認

- **目的:** 新規作成したレコードが一覧画面で正しく表示されることを確認する
- **手順:**
  1. レコードを新規作成する（確認項目2の手順）
  2. アプリの一覧画面に戻る
  3. 新規作成したレコードの各フィールドが表示されることを確認する
- **期待結果:** 会社名・担当者名・顧客ランク等が一覧に表示される
- **確認ポイント:** フィールドコードの不一致により空欄になっていないこと

## エッジケース・異常系

### 1. 空のフォーム送信

- **目的:** 全フィールド空でもエラーにならないことを確認する
- **手順:**
  1. レコード追加ページで何も入力せずに「Save」をクリックする
- **期待結果:** レコードが作成される（全フィールドが optional のため）

## 既存機能への影響確認

- シードデータで作成済みの既存レコード（サンプル株式会社A/B/C）が一覧・詳細で正常に表示されること
- 他のフィールド（department, postal_code, tel, address, email）が影響を受けていないこと
