### 1. 型チェック・リント・テスト

- **目的:** コード変更が型安全性とプロジェクト規約を満たすことを確認
- **手順:**
  1. `pnpm typecheck` を実行
  2. `pnpm lint:fix` を実行
  3. `pnpm format` を実行

- **期待結果:** すべてエラーなしで完了
- **確認ポイント:** 特に `schemas.ts` からのインポートパスが正しく解決されること

### 2. ビルド確認

- **目的:** サーバー専用モジュールがクライアントバンドルに混入していないことを確認
- **手順:**
  1. `pnpm build` を実行
- **期待結果:** ビルド成功。サーバーモジュール混入に関するエラーなし
- **確認ポイント:** Issue #1 で修正したhydration問題の再発がないこと

### 3. security/login フォーム動作確認

- **目的:** `z.coerce.number()` スキーマがクライアント側 Conform で正常動作すること
- **手順:**
  1. 管理画面のセキュリティ設定ページ（`/admin/security/login`）にアクセス
  2. パスワード最小文字数の `<select>` を変更
  3. 管理者パスワード最小文字数の `<select>` を変更
  4. パスワード複雑度の `<select>` を変更
  5. ロックアウト試行回数の `<select>` を変更
  6. フォームを送信
- **期待結果:** バリデーションエラーなくフォームが送信され、設定が保存される
- **確認ポイント:** `<select>` 要素に不正な HTML 属性が付与されていないこと（DevTools で確認）

### 4. features フォーム動作確認

- **目的:** checkbox のフルスキーマ共有でバリデーション・送信が正常なこと
- **手順:**
  1. 管理画面の機能設定ページ（`/admin/system/features`）にアクセス
  2. 各 checkbox をON/OFFに切り替え
  3. email 関連の select を変更
  4. フォームを送信
- **期待結果:** バリデーションエラーなくフォームが送信され、設定が保存され��
- **確認ポイント:** checkbox が unchecked の場合でも `.optional()` で通過すること

### 5. acl（権限管理）フォーム動作確認

- **目的:** `addPermissionSchema` への切り替え後にフォーム動作が正常なこと
- **手順:**
  1. 管理画面の ACL 設定ページ（`/admin/system/acl`）にアクセス
  2. 権限追加フォームにユーザー/グループを入力
  3. 権限を追加
  4. 権限の更新操作を実行
  5. 権限の削除操作を実行
- **期待結果:** 追加・更新・削除がすべて正常に動作する
- **確認ポイント:** 追加フォームのクライアントバリデーション、update/delete の fetcher.submit が正常動作

### 6. system-mail フォーム動作確認

- **目的:** BUILTIN/EXTERNAL 切り替え時のフルスキーマ共有が正常なこと
- **手順:**
  1. 管理画面のメール設定ページ（`/admin/system-mail`）にアクセス
  2. サーバータイプを BUILTIN に設定し保存
  3. サーバータイプを EXTERNAL に切り替え
  4. 外部サーバー設定（ホスト、ポート等）を入力
  5. フォームを送信
- **期待結果:** 両タイプで正常に保存される
- **確認ポイント:** BUILTIN 選択時に外部サーバー設定フィールドが存在しなくても `.optional()` で通過すること
