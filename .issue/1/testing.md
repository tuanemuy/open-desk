# 動作確認計画 — Issue #1: バグ: action.ts がサーバーオンリーモジュールをインポートして React hydration が失敗する

**Issue:** #1
**作成日:** 2026-04-12

---

## 確認環境

### デプロイ・起動手順
1. 依存パッケージのインストール
   ```bash
   pnpm install
   ```
2. 開発サーバーの起動
   ```bash
   pnpm dev
   ```
3. 確認用URL: http://localhost:5173

## 確認項目

### 1. サーバーオンリーモジュールエラーが解消されていること

- **目的:** Vite のクライアントバンドルビルドでサーバーオンリーモジュール参照エラーが出ないことを確認
- **手順:**
  1. `pnpm dev` で開発サーバーを起動
  2. ブラウザで http://localhost:5173/login を開く
  3. ブラウザの DevTools コンソールを確認
- **期待結果:** `[plugin:vite:import-analysis] Server-only module referenced by client` エラーが表示されない
- **確認ポイント:** コンソールにサーバーモジュール関連のエラーがないこと

### 2. React hydration が正常に完了すること

- **目的:** React のクライアントサイド hydration が成功することを確認
- **手順:**
  1. http://localhost:5173/login を開く
  2. ブラウザの DevTools コンソールを確認
- **期待結果:** hydration エラーが表示されない
- **確認ポイント:** `Hydration failed` や `There was an error while hydrating` 等のエラーがないこと

### 3. ログインフォームのバリデーションが動作すること

- **目的:** `useFetcher` ベースのフォーム送信とエラー表示が機能することを確認
- **手順:**
  1. http://localhost:5173/login を開く
  2. メールアドレス欄を空欄のまま送信ボタンをクリック
  3. エラーメッセージの表示を確認
  4. 不正なメールアドレスを入力して送信
  5. エラーメッセージの表示を確認
- **期待結果:** `fetcher.data` からエラーメッセージがフォーム上に表示される
- **確認ポイント:** ページ全体がリロードされるのではなく、SPA的にエラーが表示されること

### 4. SPA ナビゲーションが機能すること

- **目的:** React Router の Link コンポーネントによる SPA 遷移が動作することを確認
- **手順:**
  1. ログイン後（または認証済みの状態で）ポータルページにアクセス
  2. ページ内のリンクをクリック
  3. ページ遷移の挙動を確認
- **期待結果:** ページ全体がリロードされず、SPA ナビゲーションで遷移する
- **確認ポイント:** ブラウザのネットワークタブでHTMLの再取得が発生していないこと

## エッジケース・異常系

### 1. 型チェックが通ること

- **目的:** `.server.ts` リネーム後も TypeScript の型推論が正常に動作することを確認
- **手順:**
  1. `pnpm typecheck` を実行
- **期待結果:** エラーなく完了する

### 2. ビルドが成功すること

- **目的:** 本番ビルドでもサーバーオンリーモジュールの分離が正しく動作することを確認
- **手順:**
  1. `pnpm build` を実行（ビルドコマンドが存在する場合）
- **期待結果:** エラーなくビルドが完了する

## 既存機能への影響確認

- action/loader の実行ロジック自体は変更していないため、サーバーサイドの動作に影響はない
- 全ルートで action/loader が正しく解決されることは型チェックとサーバー起動で確認可能
