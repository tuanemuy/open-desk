## 確認項目

### 1. ログイン失敗時の failedLoginAttempts インクリメント

- **目的:** パスワード誤入力時に `users.failed_login_attempts` がインクリメントされることを確認する
- **手順:**
  1. 有効なアカウントで誤ったパスワードを入力してログインを試みる
  2. DBを確認し `failed_login_attempts` が 1 になっていることを確認
  3. もう一度誤ったパスワードでログインを試みる
  4. DBを確認し `failed_login_attempts` が 2 になっていることを確認
- **期待結果:** 失敗回数がログイン試行ごとにインクリメントされる
- **確認ポイント:** エラーメッセージは「Invalid login name or password」が表示されること

### 2. 閾値超過時のアカウントロック

- **目的:** 失敗回数が閾値に達した際に `locked_until` が設定されアカウントがロックされることを確認する
- **手順:**
  1. `lockout_policy` の `maxFailedAttempts` を確認する（デフォルト5回想定）
  2. 有効なアカウントで閾値回数分、誤ったパスワードでログインを試みる
  3. DBを確認し `locked_until` が設定されていることを確認
  4. もう一度（正しいパスワードでも）ログインを試みる
  5. ロックアウトエラーが表示されることを確認
- **期待結果:** 閾値到達後にアカウントがロックされ、ログインが拒否される
- **確認ポイント:** `locked_until` の値が `lockout_policy.lockoutDurationMinutes` 分後の日時になっていること

### 3. ロックアウト状態でのログイン拒否

- **目的:** ロックアウト状態のユーザーが正しいパスワードでもログインできないことを確認する
- **手順:**
  1. DBに直接 `locked_until = 現在時刻 + 30分` を設定する
  2. 正しいパスワードでログインを試みる
  3. ログインが拒否されることを確認
- **期待結果:** 「Account is locked」というエラーメッセージが表示される
- **確認ポイント:** ログインフォームにエラーが表示され、セッションが作成されないこと

### 4. ロック期限切れ後のログイン成功

- **目的:** ロック期限が切れた後に正しいパスワードでログインが成功することを確認する
- **手順:**
  1. DBに直接 `locked_until = 過去の日時` を設定する
  2. 正しいパスワードでログインを試みる
  3. ログインが成功することを確認
  4. DBを確認し `failed_login_attempts` が 0 にリセットされ、`locked_until` が null になっていることを確認
- **期待結果:** ロック期限切れ後は正常にログインでき、カウンターがリセットされる
- **確認ポイント:** セッションが正常に作成され、ダッシュボードにリダイレクトされること

### 5. ログイン成功時の failedLoginAttempts リセット

- **目的:** ログイン成功時に失敗カウンターがリセットされることを確認する
- **手順:**
  1. 有効なアカウントで2-3回誤ったパスワードでログインを試みる
  2. DBを確認し `failed_login_attempts` が増えていることを確認
  3. 正しいパスワードでログインする
  4. ログアウトする
  5. DBを確認し `failed_login_attempts` が 0 にリセットされていることを確認
- **期待結果:** ログイン成功で失敗カウンターがリセットされる
- **確認ポイント:** 次回のログイン試行が閾値回数分の猶予があること

## エッジケース・異常系

### 1. lockout_policy が未設定の環境

- **目的:** `lockout_policy` 設定が存在しない場合にロックアウトが無効として動作することを確認する
- **手順:**
  1. `system_settings` テーブルから `lockout_policy` レコードを削除する
  2. 何度も誤ったパスワードでログインを試みる
  3. アカウントがロックされないことを確認する
- **期待結果:** ロックアウトが発生せず、通常の認証フロー（成功/失敗）が機能する

### 2. 永久ロック（lockoutDurationMinutes: null）

- **目的:** `lockoutDurationMinutes` が `null` の場合、永久ロックとして動作することを確認する
- **手順:**
  1. `lockout_policy` の `lockoutDurationMinutes` を `null` に設定する
  2. 閾値回数分、誤ったパスワードでログインを試みる
  3. アカウントがロックされた後、時間が経過してもロックが解除されないことを確認
- **期待結果:** `locked_until` が非常に遠い未来の日付（9999-12-31）に設定され、事実上の永久ロックとなる

### 3. ロック期限切れ後に再度パスワードを間違えた場合

- **目的:** ロック期限切れ後にパスワードを間違えた場合、カウントが再開されることを確認する
- **手順:**
  1. DBに `locked_until = 過去の日時`, `failed_login_attempts = 5`（閾値）を設定する
  2. 誤ったパスワードでログインを試みる
  3. DBの `failed_login_attempts` が 6 になり、再ロックされることを確認する
- **期待結果:** 期限切れ後も失敗カウントは維持され、再度間違えると即ロックされる
