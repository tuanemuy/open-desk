# レコード CRUD

## レコード1件取得

`GET /k/v1/record.json`

レコードIDを指定して1件のレコードを取得する。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| id | 数値または文字列 | 必須 | レコードID |

### レスポンス

| プロパティ | 型 | 説明 |
|---|---|---|
| record | オブジェクト | レコードのフィールド情報を含むオブジェクト。各フィールドは `type` と `value` を持つ。 |

### 必要なアクセス権

- アプリのレコード閲覧権限
- 対象レコードの閲覧権限
- 各フィールドの閲覧権限

### 制限事項

- APIトークン認証の場合、データの言語はアプリ管理者の表示言語に依存する。その他の認証方式では実行ユーザーの言語に依存する。

### リクエスト例

```
GET /k/v1/record.json?app=8&id=100
```

```bash
curl -X GET 'https://sample.cybozu.com/k/v1/record.json?app=8&id=100' \
  -H 'X-Cybozu-API-Token: API_TOKEN'
```

### レスポンス例

```json
{
  "record": {
    "レコード番号": {
      "type": "RECORD_NUMBER",
      "value": "100"
    },
    "文字列1行": {
      "type": "SINGLE_LINE_TEXT",
      "value": "テスト"
    },
    "数値": {
      "type": "NUMBER",
      "value": "20"
    }
  }
}
```

## レコード複数取得

`GET /k/v1/records.json`

クエリで条件を指定して複数のレコードを取得する。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| fields | 文字列の配列 | 任意 | レスポンスに含めるフィールドコード。省略時はアクセス権のある全フィールドを返す。リクエストボディでは最大1,000件、クエリ文字列では配列インデックス0〜99まで指定可能。テーブルのフィールドはテーブルのフィールドコードのみ指定する。 |
| query | 文字列 | 任意 | レコードの絞り込み・ソート条件のクエリ文字列。省略時はアクセス権のある全レコードを取得。 |
| totalCount | 真偽値または文字列 | 任意 | `true` でレスポンスに合計件数を含める。デフォルトは `false`（`null` を返す）。 |

### レスポンス

| プロパティ | 型 | 説明 |
|---|---|---|
| records | オブジェクトの配列 | レコードデータの配列 |
| totalCount | 文字列またはnull | クエリ条件に一致するレコードの総数。`totalCount` パラメータが `false` または省略時は `null` |

### 必要なアクセス権

- アプリのレコード閲覧権限
- 各レコードの閲覧権限
- 各フィールドの閲覧権限

### 制限事項

- 1回のリクエストで取得できるレコードは **最大500件**
- デフォルトのlimitは **100件**
- offsetの上限は **10,000件**
- キーワード検索（`like` / `not like`）では検索対象レコードが100,000件に達した時点で検索が打ち切られる
- キーワード検索は部分一致ではなく単語一致で行われる

### リクエスト例

```bash
curl -X GET 'https://sample.cybozu.com/k/v1/records.json' \
  -H 'X-Cybozu-API-Token: API_TOKEN' \
  -G \
  --data-urlencode 'app=8' \
  --data-urlencode 'query=更新日時 > "2025-02-03T09:00:00+0900" order by レコード番号 asc limit 10 offset 0' \
  --data-urlencode 'fields[0]=レコード番号' \
  --data-urlencode 'fields[1]=作成日時' \
  --data-urlencode 'totalCount=true'
```

### レスポンス例

```json
{
  "records": [
    {
      "レコード番号": {
        "type": "RECORD_NUMBER",
        "value": "1"
      },
      "作成日時": {
        "type": "CREATED_TIME",
        "value": "2025-02-03T09:30:00Z"
      }
    }
  ],
  "totalCount": "50"
}
```

## レコード1件登録

`POST /k/v1/record.json`

1件のレコードを登録する。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| record | オブジェクト | 任意 | フィールドコードと値のオブジェクト。省略すると全フィールドがデフォルト値で登録される。存在しないフィールドコードは無視される。 |

### レスポンス

| プロパティ | 型 | 説明 |
|---|---|---|
| id | 文字列 | 登録されたレコードのレコードID |
| revision | 文字列 | 登録されたレコードのリビジョン番号 |

### 必要なアクセス権

- アプリのレコード追加権限
- 各フィールドの編集権限
- 作成者・更新者・作成日時・更新日時を設定する場合はアプリの管理者権限

### 制限事項

以下のフィールドには値を設定できない:
- ルックアップ（コピー元のフィールド）
- ステータス
- カテゴリー
- 計算フィールド
- 作業者
- 自動計算が有効な文字列フィールド

### リクエスト例

```bash
curl -X POST 'https://sample.cybozu.com/k/v1/record.json' \
  -H 'X-Cybozu-API-Token: API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "app": 1,
    "record": {
      "文字列1行": { "value": "テスト" },
      "数値": { "value": "20" }
    }
  }'
```

### レスポンス例

```json
{
  "id": "100",
  "revision": "1"
}
```

## レコード複数登録

`POST /k/v1/records.json`

複数のレコードを一括で登録する。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| records | オブジェクトの配列 | 必須 | 登録するレコードの一覧。各レコードはフィールドコードと値のオブジェクト。 |

### レスポンス

| プロパティ | 型 | 説明 |
|---|---|---|
| ids | 文字列の配列 | 登録されたレコードのレコードID（リクエスト順） |
| revisions | 文字列の配列 | 登録されたレコードのリビジョン番号（リクエスト順） |

### 必要なアクセス権

- アプリのレコード追加権限
- 各フィールドの編集権限
- 作成者・更新者・作成日時・更新日時を設定する場合はアプリの管理者権限

### 制限事項

- 一度に登録できるレコードは **最大100件**
- 処理に失敗すると、リクエストに指定した全レコードの登録がキャンセルされる（トランザクション）
- 値を設定できないフィールドはレコード1件登録と同様

### リクエスト例

```bash
curl -X POST 'https://sample.cybozu.com/k/v1/records.json' \
  -H 'X-Cybozu-API-Token: API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "app": 1,
    "records": [
      {
        "文字列1行": { "value": "テスト1" },
        "数値": { "value": "10" }
      },
      {
        "文字列1行": { "value": "テスト2" },
        "数値": { "value": "20" }
      }
    ]
  }'
```

### レスポンス例

```json
{
  "ids": ["100", "101"],
  "revisions": ["1", "1"]
}
```

## レコード1件更新

`PUT /k/v1/record.json`

1件のレコードを更新する。レコードIDまたは重複禁止フィールドの値で対象レコードを特定できる。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| id | 数値または文字列 | 条件付き必須 | レコードID。`updateKey` と同時に使用不可。 |
| updateKey | オブジェクト | 条件付き必須 | 重複禁止設定された文字列フィールドまたは数値フィールドのフィールドコードと値。`id` と同時に使用不可。 |
| updateKey.field | 文字列 | - | フィールドコード |
| updateKey.value | 文字列 | - | フィールドの値 |
| record | オブジェクト | 任意 | 更新するフィールドコードと値。省略するとフィールドの値は変更されない。 |
| revision | 数値または文字列 | 任意 | 期待するリビジョン番号。実際のリビジョンと異なる場合エラー。`-1` を指定または省略するとバリデーションをスキップ。 |

### レスポンス

| プロパティ | 型 | 説明 |
|---|---|---|
| revision | 文字列 | 更新後のレコードのリビジョン番号 |

### 必要なアクセス権

- アプリのレコード編集権限
- 対象レコードの編集権限
- 各フィールドの編集権限

### 制限事項

以下のフィールドは更新できない:
- ルックアップ（コピー元のフィールド）
- ステータス
- カテゴリー
- 計算フィールド
- 作業者
- 作成者・作成日時
- 更新者・更新日時
- 自動計算が有効な文字列フィールド

テーブルフィールドを更新する際は、既存の行もすべてリクエストに含める必要がある。含めない行は削除される。添付ファイルフィールドでは、既存ファイルの `fileKey` を保持して送信する必要がある。

### リクエスト例

```bash
curl -X PUT 'https://sample.cybozu.com/k/v1/record.json' \
  -H 'X-Cybozu-API-Token: API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "app": 1,
    "id": 100,
    "record": {
      "文字列1行": { "value": "更新テスト" }
    },
    "revision": 2
  }'
```

### レスポンス例

```json
{
  "revision": "3"
}
```

## レコード複数更新

`PUT /k/v1/records.json`

複数のレコードを一括で更新する。UPSERT（存在しなければ登録、存在すれば更新）にも対応。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| records | オブジェクトの配列 | 必須 | 更新するレコードの一覧 |
| records[].id | 数値または文字列 | 条件付き必須 | レコードID。`updateKey` と同時に使用不可。 |
| records[].updateKey | オブジェクト | 条件付き必須 | 重複禁止フィールドのフィールドコードと値。`id` と同時に使用不可。 |
| records[].record | オブジェクト | 任意 | 更新するフィールドコードと値 |
| records[].revision | 数値または文字列 | 任意 | 期待するリビジョン番号。`-1` または省略でバリデーションスキップ。 |
| upsert | 真偽値 | 任意 | `true` でUPSERTモードを有効にする。`updateKey` 使用時のみ有効。該当レコードが存在しなければ新規登録、存在すれば更新。 |

### レスポンス

| プロパティ | 型 | 説明 |
|---|---|---|
| records | オブジェクトの配列 | 更新結果の配列 |
| records[].id | 文字列 | レコードID |
| records[].revision | 文字列 | 更新後のリビジョン番号 |
| records[].operation | 文字列 | `"UPDATE"`（更新）または `"INSERT"`（新規登録、UPSERTモード時のみ） |

### 必要なアクセス権

- アプリのレコード編集権限
- 各レコードの編集権限
- 各フィールドの編集権限
- UPSERTモードの場合はレコード追加権限も必要

### 制限事項

- 一度に更新できるレコードは **最大100件**
- 更新できないフィールドはレコード1件更新と同様

### リクエスト例

```bash
curl -X PUT 'https://sample.cybozu.com/k/v1/records.json' \
  -H 'X-Cybozu-API-Token: API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "app": 1,
    "records": [
      {
        "id": 1,
        "revision": 4,
        "record": {
          "文字列1行": { "value": "更新1" }
        }
      },
      {
        "id": 2,
        "record": {
          "文字列1行": { "value": "更新2" }
        }
      }
    ]
  }'
```

### レスポンス例

```json
{
  "records": [
    { "id": "1", "revision": "5" },
    { "id": "2", "revision": "3" }
  ]
}
```

UPSERT時のレスポンス例:

```json
{
  "records": [
    { "id": "1", "revision": "5", "operation": "UPDATE" },
    { "id": "100", "revision": "1", "operation": "INSERT" }
  ]
}
```

## レコード削除

`DELETE /k/v1/records.json`

複数のレコードを削除する。

### リクエストパラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| app | 数値または文字列 | 必須 | アプリID |
| ids | 数値または文字列の配列 | 必須 | 削除するレコードのレコードID |
| revisions | 数値または文字列の配列 | 任意 | 期待するリビジョン番号の配列。実際のリビジョンと異なる場合削除に失敗する。省略または `-1` を指定するとバリデーションをスキップ。 |

### レスポンス

空のJSONオブジェクト `{}` を返す。

### 必要なアクセス権

- アプリのレコード削除権限
- 対象レコードの削除権限

### 制限事項

- 一度に削除できるレコードは **最大100件**
- 処理に失敗すると、リクエストに指定した全レコードの削除がキャンセルされる（トランザクション）

### リクエスト例

```bash
curl -X DELETE 'https://sample.cybozu.com/k/v1/records.json' \
  -H 'X-Cybozu-API-Token: API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "app": 1,
    "ids": [100, 80],
    "revisions": [1, 4]
  }'
```

### レスポンス例

```json
{}
```
