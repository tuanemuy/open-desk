# プロセス管理

- URL: `/k/admin/app/status?app={appId}`
- 認証: 必要（アプリ管理者権限）
- セクション: アプリ管理

## 目的

レコードに対して承認経路や業務プロセス（ワークフロー）を設定する機能。ステータスを定義し、ステータス間の遷移（アクション）を設定することで、レコードの処理フローを管理できる。

## アクセス方法

アプリのレコード一覧画面 → 「アプリを設定」リンク → 「設定」タブ → 一般設定カテゴリ → 「プロセス管理」

---

## 設定画面の構成

3つのセクションで構成される。

### 1. 有効化

| 項目名 | 型 | 説明 |
|--------|------|------|
| プロセス管理を有効にする | チェックボックス | ON/OFF切替。無効時でも設定は表示・編集可能だがレコード画面には反映されない |

### 2. ステータス設定

リスト形式で定義。

| 項目名 | 型 | 説明 |
|--------|------|------|
| ステータス名 | テキストボックス | ステータスの名前。自由入力 |
| 並び順 | ドラッグ&ドロップ | ドラッグハンドルで順序変更（最初のステータスを除く） |
| 追加ボタン | ボタン | 選択ステータスの下に新しいステータスを追加 |
| 削除ボタン | ボタン | ステータスを削除（最初のステータスは削除不可） |

- デフォルトステータス: 未処理、処理中、完了
- 最初のステータス（未処理）はレコード作成時の初期ステータスで、削除・並び替え不可
- ステータスは任意の数を追加可能

### プロセスのフロー図

ステータスとアクションの関係をビジュアルなフロー図（SVG）で表示。

| 項目名 | 型 | 説明 |
|--------|------|------|
| ステータスノード | クリック可能なボックス | 各ステータスを表示 |
| アクションノード | クリック可能なボックス | アクション名を表示 |
| エッジ（矢印） | SVG線 | ステータス→アクション→ステータスの遷移を表示 |
| ズームイン/アウト | ボタン | フロー図の拡大・縮小 |
| フィットビュー | ボタン | フロー図を画面内に収める |

### 3. プロセス（遷移）設定

テーブル形式で定義。各行がひとつのステータスからの遷移ルール。

#### カラム構成

| カラム名 | 説明 |
|----------|------|
| アクション実行前のステータス | 遷移元ステータス。作業者の設定もここ |
| アクションが実行できる条件 | アクション実行の前提条件（フィールド値による条件分岐） |
| アクション名（ボタン名）/ 実行後のステータス | ボタン表示名と遷移先ステータス |

#### アクション実行前のステータス列

| 項目名 | 型 | 説明 |
|--------|------|------|
| ステータス名 | ドロップダウン | 遷移元ステータスの選択 |
| 追加ボタン | ボタン | 新しいプロセス行を追加 |
| 削除ボタン | ボタン | プロセス行を削除（最初の行は削除不可） |
| 作業者設定 | ドロップダウン | 下記参照 |

#### アクションが実行できる条件列

| 項目名 | 型 | 説明 |
|--------|------|------|
| 条件ドロップダウン | ドロップダウン | デフォルト「すべてのレコード」。フォームのフィールドを選択して条件指定 |
| 条件を追加 | ボタン | 同一アクションに対して複数の条件行を追加 |
| 条件を削除 | ボタン | 条件行を削除 |
| 条件結合 | ラジオボタン | 「すべての条件を満たす」(AND) / 「いずれかの条件を満たす」(OR) |
| すべてクリア | ボタン | すべての条件をクリア |

#### アクション名 / 実行後のステータス列

| 項目名 | 型 | 説明 |
|--------|------|------|
| アクションのボタン名 | テキストボックス | レコード画面に表示されるボタン名（例: 処理開始、完了する） |
| 実行後のステータス | ドロップダウン | アクション実行後の遷移先ステータス |
| 追加ボタン | ボタン | 同じステータスから複数のアクション（分岐）を追加 |

## 作業者設定

各プロセス行（ステータス）ごとに、誰がアクションを実行できるかを設定。

| 設定方法 | 説明 |
|----------|------|
| 作業者を設定しない | 誰でもアクション実行可能（デフォルト: 最初のステータス） |
| 次のユーザーから作業者を選択 | 特定のユーザー/組織/グループを指定 |

作業者の指定方法:

| 指定方法 | 説明 |
|----------|------|
| ユーザーを追加 | コンボボックスでユーザーを検索・追加 |
| 組織やグループから選択 | 組織またはグループ単位で指定 |
| フォームのフィールドを追加 | ユーザー系フィールド（作成者、更新者、ユーザー選択フィールド等）を動的に指定 |

---

## 条件分岐

2つのレベルで実現:

1. **アクション分岐**: 同一ステータスから複数のアクション（ボタン）を定義 → 異なる遷移先ステータスを設定。レコード画面では複数のアクションボタンが表示される。

2. **条件付き分岐**: 各アクションに対してフィールド値ベースの条件を設定。条件を満たす場合にのみアクションボタンが表示される。条件結合はAND/ORを選択可能。

### レコード作成画面

- ステータス表示: **なし**（レコード作成時にはステー��スは表示されない）

- 保存後、レコード詳細画面に遷移した時点で初期ステータス（最初のステータス）が自動付与される

- ステータス表示: **なし**（編集モードではステータス関連の表示は一切ない）

### ステータス遷移操作のフロー

1. レコード詳細画面を開く
2. ツール���ー左端のアクションボタン（例:「処理開始」）をクリック
3. インライン確認ポップアップが展開される（アクション名 + 次のステータス + キャンセル/実行ボタン）
4. 「実行」をクリック
5. ページがリロードされ、ステータスが更新される（アクションボタンも次のステータスに対応するものに変化）
6. 終端ステータスに到���すると、アクションボタンと「現在の作業者を変更」リンクが消える

## 通知設定

プロセス管理に関する通知は「アプリの条件通知」画面で設定。

- URL: `/k/admin/app/notification?app={appId}&trigger=app`
- 通知トリガー: ステータスの更新
- 通知先: ユーザー、組織、グループ、またはフォームのフィールド

## 特記事項

- プロセス管理が無効でも設定画面のステータス・プロセス定義は表示・編集可能
- フロー図はリアルタイムで設定変更を反映
- 保存後もアプリを「更新」しなければレコード画面には反映されない
