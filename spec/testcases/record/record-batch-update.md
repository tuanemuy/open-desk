# レコード一括更新 テストケース

UC-R06: 最大100件のレコードを一括更新する。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| アプリに複数のレコードが存在する | 1件のレコードを一括更新する | レコードが更新され、recordId と新しい revision が返される | |
| アプリに複数のレコードが存在する | 100件のレコードを一括更新する（上限） | 全100件が更新され、各 recordId と revision が返される | |
| アプリにレコードが存在する | 101件のレコードを一括更新する（上限超過） | BatchSizeLimitExceededError が返される | |
| アプリにレコードが存在する | 0件（空配列）を一括更新する | BatchSizeLimitExceededError が返される（1件以上必要） | |
| 各レコードの revision が正しい | 全レコードの正しいリビジョンと有効なフィールド値を指定して更新する | 全レコードが更新され、各リビジョンが増加する | |
| あるレコードの revision が不一致 | 一括更新を実行する | RevisionConflictError が返され、全件ロールバックされる | |
| いずれかのレコードが存在しない | 一括更新を実行する | RecordNotFoundError が返され、全件ロールバックされる | |
| アプリにレコードが存在する | いずれかのレコードでフィールド値が不正 | FieldValidationError が返され、全件ロールバックされる | |
| アプリにレコードが存在する | いずれかのレコードで更新不可フィールドへの書き込みを試みる | InvalidFieldUpdateError が返され、全件ロールバックされる | |
| アプリが存在しない | 一括更新を実行する | AppNotFoundError が返される | |
| 各レコードで revision を省略する | 一括更新を実行する | リビジョンチェックがスキップされ、全レコードが更新される | |
| アプリにレコードが存在する | 全レコードを有効な値で更新する | 全レコードの modifierId と updatedAt が設定され、RecordHistory が生成される | |
| アプリにレコードが存在する | 100件中最後の1件でバリデーションエラーが発生する | 全件ロールバックされる | |
