# レコード更新（単体） テストケース

UC-R05: 1件のレコードを更新する。リビジョンベースの楽観的ロック。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| レコードが存在する（revision=1） | 正しいリビジョン（1）と有効なフィールド値を指定して更新する | レコードが更新され、revision=2 が返される | |
| レコードが存在する（revision=1） | revision=-1 を指定して更新する | リビジョンチェックがスキップされ、レコードが更新される | |
| レコードが存在する（revision=1） | revision を省略して更新する | リビジョンチェックがスキップされ、レコードが更新される | |
| レコードが存在する（revision=2） | revision=1（不一致）を指定して更新する | RevisionConflictError が返される | |
| レコードが存在する | 有効なフィールド値を指定して更新する | modifierId と updatedAt が設定される | |
| レコードが存在する | 有効なフィールド値を指定して更新する | RecordHistory が新しいバージョンで生成され、FieldDiff が記録される | |
| レコードが存在しない | レコード更新を実行する | RecordNotFoundError が返される | |
| レコードが存在する | フィールド値が不正（型不一致等）で更新する | FieldValidationError が返される | |
| レコードが存在する | 更新不可フィールドへの書き込みを試みる | InvalidFieldUpdateError が返される | |
| レコードが存在する | サブテーブルの行が不完全な状態で更新する | SubtableRowMissingError が返される | |
| レコードが存在する | 作成者（creatorId）フィールドの更新を試みる | FieldValidationError が返される（作成時限定フィールド） | |
| レコードが存在する | 作成日時（createdAt）フィールドの更新を試みる | FieldValidationError が返される（作成時限定フィールド） | |
| レコードが存在し、重複禁止フィールドがある | 既存レコードと同じ値に更新する | FieldValidationError（一意性違反）が返される | |
| レコードが存在する | 一部のフィールドのみ更新する | 指定したフィールドのみ更新され、他のフィールドは変更されない | |
| レコードが存在する | フィールド値を変更しない更新を実行する | リビジョンが増加し、RecordHistory の FieldDiff が空で記録される | |
| アプリが存在しない | レコード更新を実行する | AppNotFoundError が返される | |
