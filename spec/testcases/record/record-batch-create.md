# レコード一括作成 テストケース

UC-R02: 最大100件のレコードを一括作成する。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| アプリが存在する | 1件のレコードを一括作成する | レコードが作成され、ids と revisions（全て1）が返される | |
| アプリが存在する | 50件のレコードを一括作成する | 全レコードが作成され、各 recordId と revision=1 が返される | |
| アプリが存在する | 100件のレコードを一括作成する（上限） | 全100件のレコードが作成される | |
| アプリが存在する | 101件のレコードを一括作成する（上限超過） | BatchSizeLimitExceededError が返される | |
| アプリが存在する | 0件（空配列）のレコードを一括作成する | BatchSizeLimitExceededError が返される（1件以上必要） | |
| アプリが存在する | 全レコードの必須フィールドが正しい値を持つ | 全レコードが作成され、各レコードの RecordHistory が生成される | |
| アプリが存在する | 2件目のレコードでフィールド値が不正 | FieldValidationError が返され、全件ロールバックされる | |
| アプリが存在する | 50件目のレコードで型不一致エラーが発生する | FieldValidationError が返され、全件ロールバックされる | |
| アプリが存在しない | 複数レコードの一括作成を実行する | AppNotFoundError が返される | |
| アプリが存在する | いずれかのレコードで更新不可フィールドへの書き込みを試みる | InvalidFieldUpdateError が返され、全件ロールバックされる | |
| アプリが存在し、重複禁止フィールドが定義されている | バッチ内で重複禁止フィールドの値が重複する | FieldValidationError（一意性違反）が返される | |
| アプリが存在し、重複禁止フィールドが定義されている | 既存レコードと重複する値がバッチ内に含まれる | FieldValidationError（一意性違反）が返される | |
| アプリが存在する | 100件のレコードの最後の1件でバリデーションエラー | FieldValidationError が返され、全99件もロールバックされる | |
| アプリが存在する | 各レコードに異なるフィールド値を指定して一括作成する | 各レコードが個別のフィールド値で正しく保存される | |
