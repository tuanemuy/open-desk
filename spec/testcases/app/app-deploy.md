# アプリ公開（デプロイ） テストケース

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| PREVIEW 状態のアプリが1つ存在し、整合性チェックに問題がない | 1件のアプリをデプロイする | アプリが ACTIVE 状態になり、results に PROCESSING/SUCCESS ステータスが返却される | |
| 複数の PREVIEW アプリが存在する | 複数アプリを一括デプロイする | すべてのアプリのデプロイ結果が返却される | |
| - | appIds を空配列で送信する | バリデーションエラーが返される | |
| - | appIds に301件以上を指定する | バリデーションエラーが返される | |
| - | appIds にちょうど300件を指定する | 正常にデプロイ処理が開始される（境界値） | |
| - | appIds にちょうど1件を指定する | 正常にデプロイ処理が開始される（境界値） | |
| - | 存在しない appId を含む appIds を指定する | バリデーションエラーが返される | |
| フォームの整合性チェックに失敗するアプリ | そのアプリをデプロイする | ビジネスルール違反エラーが返される | |
| レイアウトの整合性チェックに失敗するアプリ | そのアプリをデプロイする | ビジネスルール違反エラーが返される | |
| デプロイ処理中に外部サービスエラーが発生する | アプリをデプロイする | 外部サービスエラーが返される | |
| 複数アプリのうち1つだけ検証に失敗する | 一括デプロイする | 検証に通過したアプリのみデプロイされ、失敗したアプリは FAIL ステータスとなる | |
