# カスタマイズ管理 テストケース

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| ACTIVE 状態のアプリが存在する | scope="ALL_USERS" を指定してカスタマイズを設定する | カスタマイズが設定され、appId・scope・revision が返却される | |
| ACTIVE 状態のアプリが存在する | scope="ADMIN_ONLY" を指定して設定する | 管理者のみに適用される設定になる | |
| ACTIVE 状態のアプリが存在する | scope="NONE" を指定して設定する | カスタマイズが無効になる | |
| ACTIVE 状態のアプリが存在する | desktopJs に URL タイプのファイルを指定する | PC用 JS が URL 参照で設定される | |
| ACTIVE 状態のアプリが存在する | desktopJs に FILE タイプのファイル（fileKey 指定）を設定する | PC用 JS がファイルとして設定される | |
| ACTIVE 状態のアプリが存在する | desktopCss を設定する | PC用 CSS が設定される | |
| ACTIVE 状態のアプリが存在する | mobileJs を設定する | スマートフォン用 JS が設定される | |
| ACTIVE 状態のアプリが存在する | mobileCss を設定する | スマートフォン用 CSS が設定される | |
| カスタマイズが未設定のアプリ | 新規にカスタマイズを設定する | 新しいカスタマイズ設定が作成される | |
| - | 存在しない appId を指定する | バリデーションエラーが返される | |
| アプリが DELETED 状態 | カスタマイズを設定する | ビジネスルール違反エラーが返される | |
| revision が現在の値と一致しない | カスタマイズを設定する | ビジネスルール違反エラー（楽観的ロック競合）が返される | |
| - | scope に無効な値を指定する | バリデーションエラーが返される | |
| - | FILE タイプで fileKey を未指定にする | バリデーションエラーが返される | |
| - | URL タイプで url を未指定にする | バリデーションエラーが返される | |
| - | 20MB を超えるファイルをアップロードする | バリデーションエラーが返される | |
| - | ちょうど 20MB のファイルをアップロードする | 正常に設定される（境界値） | |
