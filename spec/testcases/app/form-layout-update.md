# フォームレイアウト更新 テストケース

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| アプリにフィールドが複数存在する | すべてのフォームフィールドを含む新しいレイアウトを指定して更新する | レイアウトが更新され、appId・revision が返却される | |
| アプリにフィールドが存在する | フィールドの順序を変更したレイアウトを指定する | フィールドの表示順序が変更される | |
| アプリにグループフィールドがある | グループ内のフィールドを再配置する | グループ内の配置が変更される | |
| - | 存在しない appId を指定する | バリデーションエラーが返される | |
| アプリが DELETED 状態 | レイアウトを更新する | ビジネスルール違反エラーが返される | |
| - | 一部のフォームフィールドが rows に含まれていない | ビジネスルール違反エラーが返される | |
| - | サブテーブル内に配置不可のフィールドをサブテーブルに配置する | ビジネスルール違反エラーが返される | |
| - | グループ内にサブテーブルをネストする | ビジネスルール違反エラーが返される | |
| アプリにフィールドが1つだけ存在する | その1フィールドのみのレイアウトを指定する | レイアウトが正常に更新される（最小構成） | |
