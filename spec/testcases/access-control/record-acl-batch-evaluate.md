# レコードアクセス権の一括評価 テストケース

UC-AC12: 指定ユーザーの複数レコードに対する実効権限を一括評価する。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| アプリとレコードが存在し、パスワード認証でアクセスしている | 有効な recordIds（1件）を指定して一括評価を実行する | レコードレベルとフィールドレベルの実効権限が返される | |
| アプリとレコードが存在し、セッション認証でアクセスしている | 有効な recordIds（複数件）を指定して一括評価を実行する | 各レコードの実効権限が返される | |
| アプリとレコードが存在し、パスワード認証でアクセスしている | 100件の recordIds を指定して一括評価を実行する（上限） | 全100件の実効権限が返される | |
| アプリとレコードが存在する | 101件の recordIds を指定する（上限超過） | TooManyRecordsError が返される | |
| アプリとレコードが存在する | 0件（空配列）の recordIds を指定する | TooManyRecordsError が返される（1件以上必要） | |
| APIトークン認証でアクセスしている | 一括評価を実行する | AuthMethodNotAllowedError が返される | |
| アプリが存在しない | 一括評価を実行する | AppNotFoundError が返される | |
| いずれかの recordId のレコードが存在しない | 一括評価を実行する | RecordNotFoundError が返される | |
| 対象ユーザーが存在しない | 一括評価を実行する | UserNotFoundError が返される | |
| アプリアクセス権で閲覧・編集・削除権限が設定されている | 一括評価を実行する | アプリレベルの権限が正しく反映された結果が返される | |
| レコードアクセス権で filterCond に一致するルールがある | 一括評価を実行する | filterCond に基づいたレコードレベルの権限が正しく評価される | |
| フィールドアクセス権が設定されている | 一括評価を実行する | フィールドレベルの閲覧・編集権限が正しく評価される | |
| ユーザーがアプリ作成者である | 一括評価を実行する | isAppCreator=true として権限が評価される | |
| ユーザーがアプリ作成者でない | 一括評価を実行する | isAppCreator=false として権限が評価される | |
| アプリアクセス権、レコードアクセス権、フィールドアクセス権が全て設定されている | 一括評価を実行する | 3種類のACLが統合された実効権限が返される | |
| ユーザーが複数のエンティティ（直接、組織、グループ）経由で権限を持つ | 一括評価を実行する | 全エンティティ経由の権限が結合評価された結果が返される | |
