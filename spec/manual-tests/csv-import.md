# CSV/Excel読み込み テスト

## 概要

このドキュメントはCSV/Excelファイルからレコードを一括読み込み（インポート）する機能に関するマニュアルテストの手順書です。

対応フロー: `spec/flows/csv-import.md`

## 前提条件

### 環境
- OpenDeskにログイン済みのWebブラウザ
- テスト対象のOpenDesk環境URL

### テストデータ
- 対象アプリ（顧客リスト、アプリID: 4）へのアクセス権およびファイル読み込み権限
- テスト用CSVファイル（UTF-8、カンマ区切り）:
  ```
  会社名,部署名,担当者名,郵便番号(数字のみ),TEL(数字のみ),住所,顧客ランク,メールアドレス
  テスト株式会社A,営業部,田中太郎,1000001,0312345678,東京都千代田区,A,tanaka@example.com
  テスト株式会社B,開発部,鈴木花子,2000002,0456789012,神奈川県横浜市,B,suzuki@example.com
  ```
- テスト用CSVファイル（Shift-JIS、カンマ区切り）: 同内容のShift-JIS版
- テスト用Excelファイル（.xlsx）: 同内容のExcel版

### 事前準備
1. OpenDeskにログインする
2. 顧客リストアプリのレコード一覧画面を開く
3. テスト用ファイルをローカルに準備する

---

## TC-001: CSVファイルの読み込み（追加のみ・正常系）

**種別**: 正常系
**目的**: CSVファイルからレコードを新規追加できることを検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 顧客リストのレコード一覧画面で右上の「オプション」ボタンをクリックする | メニューが展開される |
| 2 | 「ファイルから読み込む」をクリックする | CSV/Excel読み込みウィザード画面に遷移する |
| 3 | 【ステップ1】「ファイルを選択」ボタンをクリックし、UTF-8のCSVファイルを選択する | ファイル名とサイズが表示される |
| 4 | 【ステップ2】「先頭行をファイルの列名として扱う」がONであることを確認する | ONになっている |
| 5 | 【ステップ2】文字コードを「UTF-8（Unicode）」に変更する | プレビューテーブルが正しい日本語で表示される |
| 6 | 【ステップ2】区切り文字が「カンマ」であることを確認する | カンマが選択されている |
| 7 | 【ステップ3】「レコードの追加のみ」ラジオボタンを選択する | 選択される。ステップ4が表示される |
| 8 | 【ステップ3】エラー検知時の処理で「読み込みを中止する」を選択する | 選択される |
| 9 | 【ステップ4】各フィールドの対応付けを確認する（自動マッピングされているか） | CSVの列名とアプリのフィールド名が一致する場合、自動マッピングされている |
| 10 | 「読み込む」ボタンをクリックする | 読み込み処理が開始される |

**確認ポイント**:
- 読み込み完了後、レコード一覧に新しいレコードが追加されている
- 各フィールドの値がCSVの内容と一致している

## TC-007: エラー検知時に読み込みを継続する

**種別**: 正常系
**目的**: バリデーションエラーがある行をスキップし、正常な行のみ読み込めることを検証する

テスト用CSVファイル（エラー行含む）:
```
会社名,部署名,担当者名,郵便番号(数字のみ)
正常株式会社,営業部,山田太郎,1000001
エラー株式会社,開発部,鈴木花子,12345678
正常二号株式会社,総務部,佐藤次郎,2000002
```
※ 2行目の郵便番号が8文字でバリデーションエラーとなる

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 上記のCSVファイルをローカルに保存する | - |
| 2 | CSV読み込みウィザードで該当ファイルを選択する | プレビューに3行のデータが表示される |
| 3 | 【ステップ3】「レコードの追加のみ」を選択する | 選択される |
| 4 | 【ステップ3】エラー検知時の処理で「読み込みを継続する」を選択する | 選択される |
| 5 | フィールド対応付けを設定し「読み込む」をクリックする | 読み込み処理が完了する |

**確認ポイント**:
- 「正常株式会社」と「正常二号株式会社」のレコードが追加されている
- 「エラー株式会社」のレコードは追加されていない（スキップされた）
- エラー件数として1件が通知される
